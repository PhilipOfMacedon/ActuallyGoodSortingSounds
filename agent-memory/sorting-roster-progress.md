# Sorting roster and semantic-audio progress

## Pinned source and acceptance meaning

- ArrayV source is pinned to commit `74f6ada530f0ed0ae38fe95db40ebf971a19167c`.
- [`arrayv-catalog-coverage.csv`](arrayv-catalog-coverage.csv) lists 208 selectable upstream source classes. A row is marked `implemented_and_tested` only when the app has a distinct catalog mapping and its focused behavioral/replay tests or catalog-wide tests exercise it. Trace adaptations and documented upstream corrections are called out in the row contract.
- The manifest contains **208/208 selectable source rows** pinned to the catalog revision. They resolve to 207 distinct family/variant pairs because the upstream `MergeSort` wrapper is a documented top-down configuration alias of the shared Merge strategy. The **211 registered strategies** comprise those mappings, the pre-existing Quick and Radix entries, and the canonical Stalin-discard and oriented Burnt Pancake companions. The manifest now records explicit behavior contracts, options, and verification evidence for every row; an automated check rejects the former unreviewed placeholders.

## Working architecture

- `SortingLogic` remains SDL/OpenGL-free. The catalog supplies family and stable variant identity, complexity/stability facts, supported data domains, safe limits, audio comparison roles, options and trace builders.
- `TraceBuildRequest` selects an existing builder callback. A single-job trace worker builds deterministic reversible traces; the simulation replays, rewinds, seeks and snapshots them on the app thread.
- Trace workspaces, counters, role tags, region annotations and phase IDs are model data, separate from pixel layout. The app projects those into the shared chart and workspace lanes.
- The shared sound path retains Counting/Radix event and audio-operand fixtures. Distribution methods remain the sound reference; other semantic event types route through bounded presentation summaries and the separate accent voice.
- The algorithm browser, settings list, and combo-box popups now use the common `UiScrollViewport` geometry for wheel input, clipping, visible rows and keyboard reveal. The GUI scroll refactor and current limitations are documented in [`gui-scroll-refactor.md`](gui-scroll-refactor.md). Future workspace/diagnostic panes should adopt the same viewport.

- The exchange batches add optimized/unoptimized Bubble, Binary Gnome, iterative/recursive Circle Sort, Classic 3-Smooth Comb, optimized/unoptimized Cocktail Shaker, optimized Gnome, Shove and Slope Sort. - The selection batch adds Bingo Sort, Double Selection Sort and Stable Selection Sort. Bingo groups all occurrences of each current maximum into the completed suffix. - Cycle Sort is now represented with a reversible `CarryWrite` event. The held item replaces its rank destination while the displaced item becomes the held item; the hole stays at the cycle start until the final placement.
